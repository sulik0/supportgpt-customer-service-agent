# SupportGPT 前端设计方案

> 状态：方案已确认，前端实现与本地验收已完成。本文前半部分保留设计依据，实际完成情况和未验证范围见第 12 节。
>
> 更新日期：2026-10-11。改造前代码参考：`df56423`。本轮只修改前端和本文档，不修改后端业务逻辑，不公开部署。

## 1. 产品定位与本轮范围

SupportGPT 是智能客服 Agent 平台，不是通用 Agent 构建器。用户提出订单、退款、账户或售后问题；Agent 查询资料并检查回复；员工处理需要人工确认的回复和业务结果；主管、管理员查看运行记录与管理资源。

前端需要同时服务四类人，但不能把四类人的操作混在一个页面：

| 使用者 | 主要任务 | 需要优先看到的信息 |
|---|---|---|
| 咨询用户 | 提问、补充信息、查看回复、评价 | 自己的对话、当前处理结果、下一步能做什么 |
| 客服员工 | 处理异常与待审批工单 | 为什么需要人工、已有回复、相关依据、可执行的处理动作 |
| 主管 | 定位失败请求、核实不确定的业务结果 | 工单编号、执行结果、节点策略、Tool 状态、Trace |
| 管理员 | 管理工具、Prompt 与知识文档 | 当前配置、版本、修改内容、影响范围 |

本轮优先统一上述现有功能的视觉与操作方式。保留登录、权限、审批、Session、反馈和持久执行语义，不修改 Analyzer、Skill、QA、Risk 或 Tool Governance。

`frontend-design` 已安装于本机，本轮使用现有版本，不重复安装或覆盖。设计同时参考 React 性能规范和 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)，重点检查信息层级、真实状态、键盘操作与响应式布局。

## 2. 现有实现与可用数据

### 2.1 技术栈

- React 18、Vite、JavaScript / JSX、原生 CSS、Lucide 图标。
- 改造前 `App.jsx` 使用 Hash 区分公开入口，后台页面通过组件内部状态切换；改造后使用轻量 Hash 地址记录后台页面与筛选条件，没有引入路由库。
- `src/api/client.js` 统一访问 FastAPI，员工请求使用 JWT，公开咨询使用带访客 Cookie 的请求。
- 当前测试使用 Node 内置测试运行器。没有 TypeScript、`tsconfig` 或类型检查命令。
- 不为视觉改造迁移 Next.js，不引入整套 CSS 框架、流程画布、图表库或代码编辑器。

### 2.2 页面、API 与功能边界

| 当前页面 | 主要 API / 数据来源 | 已有操作 | 不应假装已有的能力 |
|---|---|---|---|
| 用户咨询 | `/support/requests`、`/support/history`、`/feedback/user` | 提问、查看最近七天对话、开始新对话、评价本次结果 | 实时节点推送、真实客户登录、历史会话重命名或删除 |
| 员工登录 | `/auth/token` | 员工登录、退出、会话过期处理 | 公开员工注册 |
| 人工处理台 | `/staff/review-queue`、`/tickets/{id}/agent-result`、`/customer-context`、审批与 Tool Review API | 筛选工单、加载保存的回复、修改/通过/拒绝回复、按权限核实业务结果 | 打开详情自动重跑 Agent、完整高风险 Action 管理控制台 |
| Agent 运行监控 | `/observability/runs`、`/feedback/runs/{id}` | 按工单编号查询、分页、运行快照、Analyzer/QA 策略、Trace ID 与 LangSmith 链接 | 在本地完整复刻 LangSmith Span 树、实时节点耗时瀑布图 |
| 资源管理 | `/admin/resources/tools`、`prompts`、`rag-documents` | 工具启停、查看 Prompt Bundle、创建候选版本、知识文档增改删、重建索引 | 注册任意新 Tool Handler、前端直接晋级/回滚 Prompt、知识检索调试台 |
| Agent 处理流程 | 前端流程与故障场景定义 | 节点说明、场景逐步演示、Action 状态机、故障时序 | 真实执行、实时故障演练、真实 Trace 或耗时 |

API 权限仍由后端决定：人工队列允许 `agent / manager / admin`；运行监控允许 `manager / admin`；资源管理只允许 `admin`；业务结果人工确认遵循现有主管权限。

后端已有离线 Baseline、Error Analysis、Diff Report、PromptOps / EvalOps，但当前前端没有报告查询 API 或独立评测列表。第一版不新增虚构的 Evaluations 页面，也不新增没有配置接口的 Agents 页面。

### 2.3 数据真实性

- 咨询、工单与 AgentRun 从当前连接的后端读取，可以是真实执行记录；模拟客户与模拟业务资料仍需标为 Demo / Mock（演示数据）。不能把“请求确实执行了”写成“已连接真实 OMS”。
- 工单页统计只描述加载的人工处理队列；运行页平均耗时、平均 Token 等只描述当前页。没有全局统计接口，不展示“今日总量”、全局 P95 或趋势。
- 配置页面显示后端实际返回的工具、Bundle 与文档，不将仓库示例数量当成当前部署数量。
- 缺失数值显示“— / 未记录”，不能用 `0` 代替未知；零值仅在后端明确返回零时显示。
- 流程演示固定显示“静态演示，不提交请求、不调用模型”，并注明节点数量来自页面定义，而不是运行监控。

## 3. 第一阶段检查记录（改造前）

本轮阅读了页面组件、样式、API Client、后端路由权限及现有前端测试；实际打开了公开咨询页和流程演示页。未使用员工凭证进入后台，后台结论来自代码检查，不声称完成后台交互验收。

| 问题 | 代码 / 检查依据 | 拟采用的处理方式 |
|---|---|---|
| 样式来源重复，浅色页面仍依赖深色基础样式覆盖 | `frontend/src/main.jsx:4` 先加载 `index.css`，再加载 `theme.css`；`frontend/index.html:12` 仍有深色内联背景 | 分步收敛为统一 Tokens 与页面样式，删除迁移后的旧规则，不再增加第三层覆盖 |
| 部分文字过小，中文说明难读 | `index.css` 含 `0.55rem` 等字号；`workflow.css:32`、`:51` 使用 10px | 正文 14–16px，辅助信息至少 12px，代码至少 13px；不靠缩小文字塞入内容 |
| 用户咨询更像介绍页，对话区偏窄 | 1440px 桌面检查中，左侧介绍占据较大空间，对话位于右侧 | 改为居中的对话布局，介绍缩为简短的能力说明 |
| 历史加载失败仍声称“在线、已同步” | `CustomerSupportPage.jsx:277` 为固定文案；浏览器同时显示 `Failed to fetch` | 根据加载、成功和错误状态显示中文提示，不把历史同步当成服务健康证明 |
| 页面与筛选条件不能直接分享或刷新恢复 | `App.jsx:33` 将后台视图保存在本地组件状态 | 沿用 Hash，补充页面、筛选与已选工单的 URL 状态，不额外引入路由框架 |
| 运行详情抽屉缺少完整焦点管理 | `ObservabilityPage.jsx:122` 已有 Dialog 语义和 Escape 关闭，但未完整限制/恢复焦点 | 使用统一 Drawer，打开后聚焦、循环 Tab、关闭后返回触发按钮 |
| 资源页交互不统一 | `ResourceManagementPage.jsx:74` 使用 `window.prompt`；`:161` 使用 `window.confirm`；Tabs 语义不完整 | 统一表单、确认弹窗和可键盘操作的 Tabs |
| 快速切换运行详情可能显示旧请求结果 | 运行列表和详情请求未完整取消或校验最新请求 | 给页面查询增加取消与最新请求保护，沿用现有 API |
| 页面首包包含后台和演示组件 | `App.jsx` 静态引入各功能页面 | 使用 React.lazy / Suspense 按页面加载，不影响已有并行查询 |

现有代码已经包含部分 `focus-visible` 和 `prefers-reduced-motion` 规则，并有队列筛选测试、历史查询取消请求、审批防重复提交等处理。本轮会保留这些有效设计，而不是从零重写。

本地检查没有启动后端，历史加载失败是预期测试条件，不代表线上服务不可用。此轮未提交咨询、调用模型、审批工单、修改资源或运行 Docker。

## 4. 信息架构

### 4.1 页面清单

```text
公开入口
├─ 用户咨询
├─ 员工登录
└─ Agent 处理流程（静态演示）

员工后台
├─ 人工处理台                         agent / manager / admin
├─ Agent 运行监控                     manager / admin
│  └─ 运行详情
├─ 资源管理                           admin
│  ├─ 业务工具
│  ├─ Prompt 版本
│  └─ 知识文档
└─ Agent 处理流程（静态演示）
```

不增加独立 Overview。队列摘要放在人工处理台，运行摘要放在运行监控页。没有数据来源的概览卡片会增加误导，而不是帮助用户完成操作。

### 4.2 导航与地址

后台左侧固定导航，顶栏显示页面名称、简短说明、服务状态和当前员工。用户咨询不使用后台侧栏，只保留项目名称与必要入口。

已实现以下 Hash 地址：

- `#support`：用户咨询。
- `#staff`：保留旧入口；未登录显示登录页，已登录进入人工处理台。
- `#staff/review?department=shipping&ticket=123`：处理台与选中工单。
- `#staff/runs?ticket=123&offset=0&run=...`：运行筛选、分页与详情。
- `#staff/resources?tab=tools`：资源管理，Tab 可为 `tools / prompts / rag`。
- `#staff/workflow`：在后台布局中查看同一份静态流程演示。
- `#workflow`：保留公开流程演示入口；后台导航可以返回带后台布局的同一组件。

URL 参数只接受已知页面与合法值。切换筛选时重置分页；刷新和浏览器前进/后退恢复视图。登录跳转只保留站内允许的目标，不能任意跳转外部网址。前端隐藏菜单不替代后端鉴权。

## 5. 视觉规范

### 5.1 设计原则

采用 Swiss Minimal × Developer Tool × Technical Editorial：用排版和严格对齐解释复杂信息，而不是靠装饰表达“技术感”。

1. 每页只有一个主要任务和一个清楚的页面标题。
2. 列表先帮助人找到记录，详情再解释原因和依据；不把所有内容同时铺成卡片。
3. 中文写清楚谁做什么，例如“这个回复需要人工确认”，而不是“人工治理闭环”。内部节点名、版本和 Trace ID 使用英文技术术语。
4. 用细边框、留白与字号划分层级。蓝色只用于关键操作、链接、选中与键盘焦点。
5. 页面辨识度来自工单、节点策略、证据与执行结果，不来自渐变、发光或装饰性大数字。

### 5.2 Design Tokens

| 类别 | Token 建议 | 值 / 用法 |
|---|---|---|
| 主背景 | `--color-background` | `#FFFFFF` |
| 次级背景 | `--color-surface-muted` | `#F7F8FA`，侧栏、表头、代码容器 |
| 边框 | `--color-border` | `#E5E7EB`，1px |
| 主文字 | `--color-text` | `#111827` |
| 次级文字 | `--color-text-secondary` | `#64748B` |
| 强调色 | `--color-accent` | `#2563EB`，关键操作、链接、选中与焦点 |
| 成功 | `--color-success` | `#15803D`，成功文字/图标；淡色底 `#F0FDF4` |
| 警告 | `--color-warning` | `#B45309`，需注意/待确认；淡色底 `#FFFBEB` |
| 错误 | `--color-danger` | `#B91C1C`，失败/危险操作；淡色底 `#FEF2F2` |
| 间距 | `--space-*` | 4、8、12、16、24、32、40、48px |
| 圆角 | `--radius-*` | 按钮/输入框 6px，卡片 8px，弹窗 12px |
| 动效 | `--duration-fast` | 160ms，颜色与轻量位移；不使用 `transition: all` |

默认无阴影。浮层允许轻微阴影帮助区分遮挡关系；普通卡片仅用边框。状态始终有文字或图标，不能只靠红绿区分。Disabled 使用明确的不可用样式和必要说明，不简单让整段内容低透明度而难以阅读。

### 5.3 字体与密度

- 界面字体：Inter + Noto Sans SC；回退到系统中文字体。代码、ID、JSON：JetBrains Mono + 系统等宽字体。
- 页面标题 24px / 32px，区域标题 18px / 28px，小标题 16px / 24px。
- 正文与表单 14px / 22px；咨询消息 16px / 26px；辅助文字 12px / 20px；代码 13px / 20px。
- 普通字重 400，标题和关键字段 600；不使用全页加粗或中文过度负字距。
- 表格数值右对齐并采用 tabular numbers（等宽数字）；ID 显示短值，详情可查看/复制完整值。
- 字体优先使用可合法分发的本地 WOFF2；中文字体评估按需子集，不能把完整的大型字体直接塞入首包。字体暂不可用时仍保证系统字体布局正确。本阶段不下载字体或引入第三方品牌素材。

### 5.4 布局与响应式

| 尺寸 | 布局规则 |
|---|---|
| ≥1024px | 224px 后台侧栏、64px 顶栏、24px 内容内边距；人工处理台采用约 340px 队列 + 自适应详情 |
| 768–1023px | 收紧导航和留白；详情空间不足时切换列表/详情，而不是压缩所有字号 |
| <768px | 顶栏与可收起导航；列表、详情单列；详情提供明确返回按钮；抽屉变为全屏面板 |

主要内容采用统一网格，后台宽屏内容上限约 1480px；咨询主体宽度约 880px。组件使用 `min-width: 0`，长 ID/JSON 不撑开页面。

桌面按钮高度通常 36px，移动端交互区域至少 44px；移动输入框 16px，避免输入时页面自动缩放。表格只在自身容器内横向滚动；核心字段优先转为移动列表。固定输入区要考虑软键盘和 safe area（设备安全区域），不能遮住消息或提交结果。

## 6. 核心页面设计

### 6.1 用户咨询

页面以聊天为中心，不再使用大型宣传标题与左右各半的布局。

```text
┌ SupportGPT 智能客服 ────────────── 处理流程 / 员工入口 ┐
│ 订单、退款、账户和售后问题                              │
│ 演示客户 [选择]                         [开始新对话]   │
├───────────────────────────────────────────────────────┤
│ 最近七天的对话 / 日期分组                              │
│ 用户问题                                              │
│ Agent 回复                                            │
│ [如需人工：当前情况、具体原因、用户下一步]              │
│ [本次回复评价，仅在已有反馈凭证时显示]                  │
├───────────────────────────────────────────────────────┤
│ [输入问题或补充订单信息……]                   [发送]   │
│ 范围说明 / 隐私提示 / 实际加载状态                     │
└───────────────────────────────────────────────────────┘
```

- 保留最近七天历史、客户切换、新 Session、访客归属和反馈幂等逻辑；不因为重设计混合不同用户的对话。
- 无对话时显示三条真实支持范围内的示例问题；已有对话后收起引导，让消息占据主要空间。
- 加载历史显示“正在加载最近七天的对话”；成功显示加载范围；失败显示“暂时无法加载历史对话，请重试”。不无条件显示“在线”。
- 请求进行中只显示“正在处理您的问题”，不伪造当前执行到哪个节点，也不假装已有 streaming（流式输出）。
- 普通能力范围说明、等待人工、服务失败分别显示，不能把所有情况都写成“已转人工”。仅依据后端实际返回的安全回复和状态展示，不公开内部草稿或敏感证据。
- 刷新后没有反馈凭证的历史回复不增加不可用的评价按钮；评价成功与重复提交显示明确结果。

### 6.2 人工处理台

```text
┌ 导航 ┬ 人工处理台                         队列摘要 / 刷新 ┐
│      ├───────────────────┬───────────────────────────────┤
│      │ 搜索、部门等筛选  │ 工单 #123 · 用户原始问题       │
│      │                   │ 为什么需要人工处理            │
│      │ 工单列表          │ 已保存回复 / 编辑区           │
│      │ 状态、部门、时间  │ Tool / KB 依据（按需展开）     │
│      │                   │ 业务结果核实（如存在）         │
│      │                   │ [通过] [修改后通过] [拒绝]     │
└──────┴───────────────────┴───────────────────────────────┘
```

- 队列保留已有部门、优先级、情绪与关键词筛选。明确显示“筛选结果 X 条”，并支持一键清除。
- 详情先显示原始诉求和人工介入原因，再显示可编辑回复与依据，运行指标放在次级区域。
- “回复审批”和“核实外部业务执行结果”分开显示，不能让客服误以为通过回复就完成退款审批。
- 打开工单仍只加载已保存结果，不触发新 Agent 执行。手动评测继续按原权限、明确点击后调用。
- 提交时锁定当前动作，显示结果后刷新相关记录；失败保留编辑内容。切换工单或离开时，对未保存编辑进行确认。
- 没有选中记录、队列为空、筛选无结果、查询失败分别使用不同提示。

### 6.3 Agent 运行监控

以数据表呈现历史，以详情面板解释一次执行。不把此页做成缺乏数据来源的监控大屏。

```text
Agent 运行监控                       [在 LangSmith 查看]
[工单编号] [查询] [清除]              当前筛选记录总数
当前页：平均耗时 / 平均 Token / 本次建议人工的记录数
──────────────────────────────────────────────────────
北京时间 | 工单 | 本次结果 | 模型 | QA | Token | 耗时
──────────────────────────────────────────────────────
分页                                  每页 20 条

运行详情：概况 → Analyzer / QA 策略 → 执行路径 →
Tool 结果 → 知识引用 → 脱敏快照 → Trace / 版本信息
```

- 保留北京时间格式，显示“北京时间（UTC+8）”；数值不带虚构趋势。
- Analyzer 与 QA 的 rule / Jev / LLM 标签有文字说明，不把策略当作质量评级。
- 区分“本次运行建议人工”和“工单当前正在待审批”；如果没有工单最新状态，就不能冒充实时状态。
- 执行路径明确是已保存的节点顺序，不能在没有 Span 数据时画出精确耗时、并发关系或伪瀑布图；完整 Trace 跳转 LangSmith。
- Trace、Run ID 和版本可复制，复制失败给出提示。LangSmith 链接仅使用公开项目地址；API Key 始终留在后端。
- 快速切换记录时取消/忽略旧详情请求；详情加载失败不保留上一条记录的内容。

### 6.4 资源管理

三类资源共用 Tabs、筛选栏、表格、详情与编辑样式，但保留各自的业务操作。

- **业务工具**：表格展示名称、说明、读写类型、风险、角色、版本、启用状态；Schema 在详情中展开。停用必须填写原因并确认；不新增注册 Handler 或绕过审批的执行按钮。
- **Prompt 版本**：先展示 production / staging 指向的真实 Bundle，再展示版本列表与候选编辑器。系统 Prompt 与用户模板按 Analyzer / Resolver / QA 分组；保存前展示修改摘要。本轮只支持当前 API 已有的候选创建，不伪装发布和回滚。
- **知识文档**：列表可根据已加载数据筛选标题、类别与版本；编辑区包含现有字段和 Metadata JSON 校验。删除说明影响范围；重建索引显示进行中、成功或失败，不能与普通保存混为一谈。
- 每个 Tab 有独立 Loading / Empty / Error 状态；一个接口失败不能让其他资源看起来“数量为零”。
- 长文本和 JSON 使用浅色代码容器、可读字号与局部滚动，不默认增加大型编辑器依赖。

### 6.5 处理流程与故障演示

保留现有节点说明、场景切换、状态机和六套故障时序。统一为技术文档式排版：简短标题、流程主体、右侧说明；移动端先流程再详情。

持续显示 Demo 标记，不将“下一步”按钮写成“执行 Agent”。节点名用等宽字体，解释用中文；选中蓝色，成功/警告/错误颜色仅在该演示场景有相应语义时使用。

Action、Outbox、Worker Lease、Review 继续分区解释；保留可阅读的文字/表格替代视图，不让 SVG 成为唯一信息来源。按实际配置描述 Mock 与参考 OMS，不笼统宣称所有线上工具都连接真实业务系统。

### 6.6 登录

使用与后台一致的简洁白色表单，保留返回咨询入口。账号与密码有明确标签、正确的 `autocomplete` 和提交状态；错误写在表单内，不使用浏览器 Alert。没有公开员工注册入口，不在页面提供生产账号或密钥。

## 8. 交互、可访问性与安全要求

- 导航使用可分享链接，动作使用 Button。每页一个主标题，提供跳到主要内容的链接。
- 所有图标按钮有可读名称；可见焦点不能被边框或滚动容器遮住；不只支持鼠标悬停。
- 表单有真实 Label；错误关联到字段；提交结果使用合适的 `aria-live`，聊天历史不反复朗读所有旧消息。
- 弹窗和抽屉聚焦内部、支持键盘关闭，并将焦点返回原按钮。关闭可由用户控制，不能因为请求刷新突然消失。
- 普通刷新、历史恢复和页面切换不能触发模型调用、审批或资源修改。写操作只在明确操作后发起，使用现有幂等与权限机制。
- 删除、拒绝、停用和放弃未保存编辑有具体确认文案；不改变后端 Action / Approval 语义。
- `prefers-reduced-motion` 下取消非必要动效；放大到 200% 后主要内容仍可阅读和操作。
- 前端只使用可公开的配置，例如 API 地址或 LangSmith 项目链接；不读取、展示或打包 Jev / LLM / LangSmith 密钥。JSON 快照沿用后端脱敏结果，不自行请求原始敏感对象。
- 401 使用已有登录过期流程；403 显示没有权限，不误导为系统故障。不要为浏览器验证伪造生产员工身份。
