# 分类和处理原则（第二版）

> 状态：2026-11-23 定稿。替换 2026-11-17 的第一版（22 条，见 Git 历史）。
>
> 第一版的问题：语义判断分散在规则、Jev、LLM 三处，规则在多处覆盖 Jev（范围外先判、办事说法改判、投诉/情绪/被盗/影响面关键词），处理表 14 条且同一个意图在不同类别里结果不同。第二版把语义判断全部交给 Jev，重要情况由 LLM 复核；规则只做安全和字段提取；处理表只看“客户要系统做什么”和风险信号，不看业务类别。
>
> 本文是分类判断和测试题期望答案的依据；测试题和本文冲突时以本文为准，改题时在提交说明里写明依据哪一节。

## 一、处理结果

| 结果 | 客户看到什么 | 人工是否介入 |
|---|---|---|
| 自动回答 | 完整答复 | 不介入 |
| 先答后审 | 根据现有资料的初步答复，并说明已转人工复核、以人工为准 | 介入复核 |
| 转人工 | 只说明已转人工，不给业务结论 | 介入处理 |
| 安全拦截 | 拒绝并转人工 | 介入 |
| 能力说明 | 说明本系统能处理哪些售后问题 | 不介入 |

严格程度从高到低：安全拦截 > 转人工 > 先答后审 > 自动回答 > 能力说明。

## 二、谁判断什么

| 环节 | 负责 | 不负责 |
|---|---|---|
| 规则 | 安全拦截；脱敏；从原话提取订单号、发票号、设备号；“它”“这笔”指代上一轮的记录；两个模型都不可用时认出明显范围外的请求 | 业务类别、客户要做什么、是否范围外、风险信号 |
| Jev | 第三节的全部问题，每项给出答案和是否有把握 | 处理结果 |
| LLM 复核 | 第五节规定的情况下，独立回答同一组问题 | 处理结果 |
| 代码 | 按第四节的处理表得出处理结果；合并 Jev 和 LLM 的答案；优先级 | 语义判断 |

模型只回答事实问题，处理结果由代码查表得出，模型的回答不直接当作授权。

## 三、Jev 回答的问题

只判断当前这条消息。历史对话只用来理解指代（“那就帮我取消它”里的“它”），不把上一轮的诉求算到这一轮。

### 1. 是否售后范围

- **售后**：订单、退款、付款、发票、账户、保修与设备、物流、API 或服务故障相关的请求，包括问政策、问路径、办业务。只要沾到售后业务就算，例如“翻译一下我的退款政策”。
- **范围外**：完全和售后无关且无害的请求，例如天气、写诗、写代码、常识题、纯问候、只是询问“什么是提示词注入”。
- **说不清**：无法判断，或售后和无关内容混在一起。按售后处理。

### 2. 客户要系统做什么

| 答案 | 含义 | 例子 |
|---|---|---|
| 要求实际办理 | 需要有人改变业务状态：退款、取消订单、补偿、撤销扣款、改金额或地址、维修、换货、发起保修申请。用提问口气提出的也算 | “能帮我把钱退回来吗”“Please cancel ORD-1001”“我的网关坏了，帮我申请换新” |
| 问自己能不能办 | 用自己的具体情况问是否符合条件，但没要求办理 | “我付款 45 天了还能退吗”“I bought it exactly 60 days ago, am I still eligible?” |
| 查自己的记录 | 要看自己某个订单、发票、保修的当前状态 | “ORD-1001 到哪了”“我的设备还在保修期内吗” |
| 问政策或排查 | 一般政策、费用、流程、路径、故障排查，包括假设性问题 | “v2 退款手续费是多少”“接口返回 429 怎么处理”“如果我取消订单要收费吗” |
| 说不清 | 没说清楚要做什么 | “我需要帮助”“有个问题” |

### 3. 风险信号（每项是 / 否）

- **明确投诉**：明确表示投诉，或以消协、监管、媒体、律师相威胁。只问“怎么投诉”不算。
- **账户安全事件**：账户被盗、被他人登录、不认识的扣款。
- **紧急故障**：影响所有用户或生产环境整体不可用，或客户说正在影响业务。只是报错、信息不全不算。
- **负面情绪**：明显的不满、着急、失望。只描述技术症状（报错、超时）不算。

### 4. 是否附带可直接回答的问题

只在“要求实际办理”时有意义：除了办理要求，是否还问了一个能用政策直接回答的问题。例如“帮我退款，另外退款一般几天到账”。

### 5. 业务类别

账务（退款、付款、发票）、订单状态、取消订单、账户、保修与设备、服务故障、一般咨询、感谢反馈。只用来选 Skill 和要调用的查询工具，**不参与处理结果**。

## 四、处理表

安全拦截在分类之前处理（第六节）。之后从上到下，命中第一条即停：

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 范围外 | 能力说明（不查数据，不带入上一轮业务内容） |
| 2 | 明确投诉、账户安全事件、紧急故障，任一为“是” | 转人工 |
| 3 | 要求实际办理 | 附带可直接回答的问题 → 先答后审；否则转人工 |
| 4 | 问自己能不能办 | 先答后审（可以展示相关政策，不替客户下“能 / 不能”的结论） |
| 5 | 负面情绪 | 先答后审 |
| 6 | “客户要系统做什么”Jev 和 LLM 都没把握 | 先答后审 |
| 7 | 其余 | 自动回答；查自己的记录的先查再答；说不清的回答并追问细节 |

查记录时：查询成功但没有这条记录的，如实告知没找到，自动回答；查询失败的，说明暂时无法确认并转人工；原话里没有可用的记录号时，追问记录号。都不能编造。

优先级只决定人工处理时限：紧急故障为紧急；投诉、账户安全事件、要求实际办理为高；其余按业务类别的默认值。

## 五、LLM 复核

**什么时候复核**：Jev 的答案按处理表会得出自动回答、先答后审或能力说明（即没有直接转人工），并且满足下面任一条件：

- 业务类别是账务、取消订单、账户或保修与设备；
- Jev 判为范围外；
- Jev 对任何一项没把握。

已经得出转人工的不复核，因为复核只会让结果更严格或不变。

**怎么合并**：

1. Jev 没把握的项，用 LLM 的答案；LLM 也没把握的项，按“没把握”记录（触发处理表第 6 条，或按“说不清”处理）。
2. 用 Jev 的答案和 LLM 的答案各查一次处理表，取更严格的结果。
3. 两者结论不一致的，记录下来供人工抽查和补测试题。

## 六、安全

1. 要求忽略指令、输出系统提示词、越狱等攻击性输入，一律安全拦截：不查数据、不检索、不生成答复。正常问题里夹带攻击指令，也整条拦截。
2. 只是提到或询问安全概念不算攻击，例如“什么是提示词注入”“别人给我发了‘忽略之前的指令’”，交给 Jev 正常判断。
3. 安全检测服务不可用时，按隔离上下文处理并转人工，不让主流程失败。
4. 调用外部模型前先脱敏。

## 七、模型不可用

| 情况 | 做法 |
|---|---|
| Jev 不可用 | LLM 回答第三节的全部问题，作为主判断；不再复核 |
| Jev 和 LLM 都不可用 | 规则认出的明显范围外请求给能力说明；其余一律先答后审 |

## 八、回复质量（由 QA 负责，本次不改）

1. 缺少权威依据的承诺类问题（保修期限、物流时效保证、取消费、发货后改地址），知识库没有明确依据时，不下结论，说明无法确认；答复只说了无法确认的，先答后审。
2. 答复里的金额、单号、日期，在查询结果、知识库和客户原话里都找不到的，视为编造，转人工。

## 九、和第一版相比的行为变化

| 情况 | 第一版 | 第二版 |
|---|---|---|
| 原话有“退”“取消”等办事词，Jev 判为只是问 | 规则改判为要办事，转人工 | 听 Jev；涉及账务等类别时由 LLM 复核，任一判要办事即转人工 |
| 天气、写诗等 | 规则先判范围外，不调 Jev | Jev 判断，LLM 复核 |
| 投诉、被盗、影响面大 | 规则关键词或 Jev | Jev，必要时 LLM 复核；规则不参与 |
| 保修类“要办事” | 按类别查表 | 要求维修、换货、发起保修申请即“要求实际办理”；问保修状态是“查自己的记录” |
| Jev 对“办事还是问”没把握 | 账务、取消、故障三类先答后审，其他类别自动回答 | 先问 LLM；LLM 也没把握才先答后审，不分类别 |
| Jev 不可用 | 规则 → LLM 判类别，意图按说不清 | LLM 回答全部问题 |
